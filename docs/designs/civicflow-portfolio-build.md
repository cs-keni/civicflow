## Accepted Scope (added to this plan)

### Swagger JSON CI artifact (closes TODO-2)

Generate `docs/swagger.json` in CI via `dotnet swagger tofile` and commit it to the repo.

**Implementation notes:**
- Prerequisite: `dotnet tool install -g Swashbuckle.AspNetCore.Cli` must run as a CI step before the swagger tofile command.
- `Program.cs` must not require a live DB connection at startup during swagger generation. **Recommended approach**: Set `ASPNETCORE_ENVIRONMENT=SwaggerGen` in the CI step and add an explicit guard in `Program.cs`: `if (builder.Environment.EnvironmentName == "SwaggerGen") { builder.Services.AddDbContext<CivicFlowDbContext>(o => o.UseInMemoryDatabase("swagger")); }` — this is explicit, avoids environment-naming ambiguity, and does not interfere with Development or Production profiles. Do NOT use `if (!builder.Environment.IsDevelopment())` — CI is not the Development environment, so that guard would leave EF Core trying to connect to SQL Server in CI. **Simplest alternative**: Generate `docs/swagger.json` locally once during Phase 6 setup and commit it as a tracked static file, then regenerate manually when the API contract changes — this avoids the CI startup problem entirely.
- **Recommended strategy**: Generate locally once (during Phase 6 setup), commit `docs/swagger.json` as a tracked static file, and regenerate manually when the API contract changes. This is the simpler path and avoids CI write-back complexity entirely.
- **Alternative (CI auto-generation)**: Generate in CI via `git config user.email github-actions@github.com && git add docs/swagger.json && git commit -m "chore: update swagger.json" --allow-empty && git push`. Requires `contents: write` permission on the CI job token. Choose this if you want the artifact to stay automatically up-to-date.

### GitHub Actions AI matrix (closes TODO-3)

Extend `ci.yml` with a matrix strategy for AI provider testing.

**CI YAML structure — use two separate jobs, not a matrix:**
```yaml
jobs:
  test-mock:
    runs-on: ubuntu-latest
    env:
      AI_PROVIDER: mock
    steps:
      # ... restore, build, test steps

  test-real-ai:
    runs-on: ubuntu-latest
    if: github.event_name == 'workflow_dispatch' && secrets.ANTHROPIC_API_KEY != ''
    env:
      AI_PROVIDER: real
      ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
    steps:
      # minimal connectivity check only — call a ≤50-token prompt ("Say OK")
```

**Why two jobs, not matrix:** GitHub Actions matrix `include` does not support conditional inclusion — entries in `include` always run. A job-level `if:` on a named job is the correct way to make a job run only on `workflow_dispatch`.

**Implementation notes:**
- `test-mock` runs on every push and PR (always required to pass).
- `test-real-ai` runs only on manual `workflow_dispatch` trigger AND only when `ANTHROPIC_API_KEY` secret is set. The `secrets.ANTHROPIC_API_KEY != ''` expression works correctly in job-level `if:` conditions.
- The real AI check calls a minimal no-op prompt (≤50 tokens) to verify the API key is valid without incurring significant cost.
- **Precondition**: `ANTHROPIC_API_KEY` must be added as a GitHub Actions repository secret under Settings → Secrets and variables → Actions before the `workflow_dispatch` job can run successfully.
- **Branch protection warning**: Do NOT mark `test-real-ai` as a required status check. A skipped job (because `workflow_dispatch` wasn't triggered) does not satisfy required checks — it would block every PR. Only `test-mock` should be required.

| | Network failure | `HttpRequestException` |

| | Response is valid but empty string | — (silent) |

| Exception class | Rescued? | Rescue action | User sees |
|----------------|----------|---------------|-----------|
| `AnthropicException` (timeout) | Y | Catch → log + return `[]` / `null` | "Suggestions unavailable" / "Generate manually" |
| `AnthropicException` (rate limit) | Y | Catch → log + return safe default | Same fallback UI |
| `JsonException` | Y | Catch → log + return safe default | Same fallback UI |
| `HttpRequestException` | Y | Catch → log + return safe default | Same fallback UI |
| Refusal text (no exception) | Y (content check) | Check before returning; return safe default if refusal | Same fallback UI |
| Empty response | Y (null/empty check) | Return safe default | Same fallback UI |
